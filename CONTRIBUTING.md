# Contributing

Thank you for helping maintain Awesome RSI in AI.

## Scope

Contributions should explain an identifiable improvement mechanism, an evaluation instrument, or a relevant limitation. Suitable topics include generated training data, task curricula, persistent memories and skills, prompt and program search, evaluator learning, editable improvers, and automated research.

Generic model announcements and agent frameworks without an explicit connection to these mechanisms are outside the list's scope. A resource need not demonstrate RSI to belong, but its description must make its role clear.

## Entry Format

```md
- [Name: Paper Title](https://primary-source.example/paper) (2026) - One sentence explaining what changes, what feedback drives it, or what the resource evaluates. [Code](https://github.com/owner/repo) · [Survey ref. N](docs/references.md#ref-N)
```

Use the first public year, a primary paper or official publication page, and author-linked code when available. Omit missing code links and omit the survey-reference suffix for work not cited in v1. Never invent a reference number. State a specific mechanism rather than promotional claims or an unsupported assertion that RSI is solved.

## Placement and Verification

- Place a resource in the most specific existing subsection and avoid duplicate entries.
- Check the title, author record, first public year, and destination URL against the primary source.
- Check that implementation links are official; identify independent reproductions explicitly.
- Explain whether the method revises a current output, retains solver changes, or changes how later updates are produced.
- Support performance claims with the exact tested configuration, data split, budget, and comparison; prefer concise mechanism descriptions in the README.
- Disclose your relationship to a submitted resource in the pull request.
- Check Markdown anchors, local paths, and bibliography cross-references after editing.

The v1 reference archive is a provenance record. Keep its original numbering stable. Submit bibliographic corrections with supporting primary-source evidence and document the correction in the archive notes rather than silently overwriting the record. Later papers may be added to the curated list with a clear update note; they should not be presented as part of the original survey's search window.

Small pull requests with a clear rationale are welcome. Include the proposed category, paper URL, optional code URL, and why the resource belongs.
